# <ชื่อโปรเจกต์> — กติกาบังคับทุก session (LANES)

ไฟล์นี้**โหลดอัตโนมัติทุก session** ไม่ว่าใครเปิด เปิดยังไง หรือถูก chip ต่อมากี่ชั้น
เขียนไว้เฉพาะข้อที่**พลาดไม่ได้** · รายละเอียดทั้งหมดอยู่ที่ **`docs/team/CHARTER.md` — อ่านก่อนเริ่มงานเสมอ**

---

## 🔴 5 ข้อที่ห้ามพลาด

### 1. ห้าม `push` ขึ้น `main` เอง
coordinator merge เท่านั้น · งานของคุณอยู่บน branch `parallel/<แผนก>-<งาน>` เสมอ

### 2. จบงาน = 4 อย่าง ไม่ใช่ 3
```
① build + typecheck + tests เขียวครบ
② commit สุดท้ายขึ้นต้นด้วย  done(<แผนก>-<งาน>):
③ อัปเดต docs/team/status/<แผนก>.md
④ push แล้ว "ยืนยันว่าถึงจริง"  ← ข้อที่ถูกลืมบ่อยที่สุด
```

### 3. 🚨 ก่อนบอกใครว่า "ส่งแล้ว" ต้องรันสามคำสั่งนี้และได้ผลว่าง
```bash
git status --porcelain               # ต้องว่าง = ไม่มีอะไรค้างไม่ได้ commit
git log --oneline @{u}..HEAD         # ต้องว่าง = push ถึง remote จริง
git log --oneline origin/main..HEAD  # ต้องอยู่บน parallel/ และ push แล้ว
```
> **`git commit` ผ่าน ≠ ของถึงมือคนอื่น**
> **งานที่ commit แล้วแต่ไม่ push = งานที่ไม่มีอยู่จริงสำหรับทุกคนนอกจากคุณ**

**ถ้าคุณอยู่บน branch `claude/<ชื่อสุ่ม>` (worktree ที่ระบบสร้างให้) แปลว่ายังไม่ได้ push เข้าระบบทีม:**
```bash
git push -u origin HEAD:parallel/<แผนก>-<งาน>
```

### 4. ห้ามแตะไฟล์นอกเขตแผนกตัวเอง
เขตไฟล์อยู่ใน `docs/team/ownership.json` · อยากให้แก้ไฟล์กลาง → **เขียน request ถึง coordinator ในรายงานจบงาน**
**และห้ามเริ่มงานถ้ามี session อื่นแตะไฟล์เดียวกันอยู่** — เช็ค `git fetch && git branch -r | grep parallel/`

### 5. งานพวกนี้ต้องผ่านเจ้าของโปรเจกต์เท่านั้น — **ห้ามทำเอง ห้าม "ลองก่อน"**
- เขียน/ลบข้อมูลบน production
- รัน migration
- deploy
- publish

**เขียนสคริปต์ส่งให้ coordinator รัน** — พร้อมด่านตรวจในไฟล์ที่ล้มตัวเองถ้าผลไม่ตรงที่คาด

## 🔢 กติกาเรื่องตัวเลข

- **เลขทุกตัวต้องมีหน่วยติดตัว** — `"9 แถว / 11 ครั้ง"` ไม่ใช่ `"11"`
- **ยอดย่อยต้องบวกได้เท่ายอดรวม และเขียนกำกับ** (`70+1+1+1 = 73 ✓`)
- **เลขที่เป็นขอบล่างต้องเขียนว่าเป็นขอบล่าง**
- **เลขที่กระทบกันไม่ลง = มีอันหนึ่งผิด ห้ามส่งต่อ**
- **ตัวเลขต้องมาจากการวัด ไม่ใช่บวกในหัว** — และ**เขียนว่าใครวัด**
- **เทียบก่อน/หลัง ต้องรันคำสั่ง *ตัวเดิม*** ไม่ใช่คำสั่งที่ตอบคำถามเดียวกัน

## 🧪 กติกาเรื่องการตรวจ

- **สแกน/probe ที่เขียนเอง ต้องสอบเทียบกับเคสที่รู้คำตอบก่อนใช้**
- **"เจอเยอะผิดปกติ" = เครื่องมือพัง ไม่ใช่โค้ดพัง**
- **ด่านตรวจต้องพิสูจน์ว่ามันแดงได้จริง — และเขียวได้จริง**
- **ด่านต้องวัดสิ่งที่ขั้นตอนนี้ทำ ไม่ใช่ความสมบูรณ์แบบของทั้งระบบ**
- **เปิดของจริงดูด้วยตาก่อนปิดงาน** — บั๊กที่เจอบ่อยที่สุดผ่าน typecheck/build/tests หมด

## 🧭 จะเปิด session ใหม่ หรือใช้ subagent?

> ## **งานที่ไม่จบด้วย commit → subagent · งานที่จบด้วย commit → session**

**subagent:** วัด · กวาด `grep` · ยิงคิวรีนับ · อ่าน log ยาวๆ ⇒ **output ยาวๆ อยู่ในบริบทของ subagent ไม่ใช่ของคุณ**
**session:** งานที่ต้องตัดสินใจระหว่างทางและ **เถียงกลับได้**
**เพดาน: session พร้อมกัน 3–5 อัน**

**chip prompt ต้องมีครบ 4 อย่าง:**
1. บอกว่าเป็นแผนกอะไร + สั่งให้อ่าน `docs/team/CHARTER.md` + `lessons/<หมวดที่เกี่ยว>.md`
2. ระบุ branch `parallel/<แผนก>-<งาน>`
3. เช็คก่อนว่าไม่มี session อื่นแตะไฟล์ชุดเดียวกัน
4. **บอกกับดักที่คุณเพิ่งเจอ** — คนใหม่ไม่รู้สิ่งที่คุณรู้

## ✉️ ก่อนส่งข้อความหา session อื่น

1. **`git fetch` แล้วดูว่าปลายทางแก้ไปแล้วหรือยัง**
2. **การตัดสินใจของเจ้าของโปรเจกต์ต้องลง `docs/team/decisions.md`** ไม่ใช่อยู่แค่ในบทสนทนา
3. **ข้อความ = คำตัดสิน + เหตุผล 1 บรรทัด + สิ่งที่ต้องทำ ≤3 ข้อ**

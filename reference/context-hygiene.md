## อาการ

- session เริ่ม "ลืม" กฎที่เขียนไว้ชัดเจน
- กฎที่อยู่**กลางไฟล์**ถูกมองข้ามบ่อยกว่ากฎที่อยู่หัวหรือท้าย
- ยิ่งเขียนกฎเพิ่ม ยิ่งพลาดบ่อยขึ้น (ไม่ใช่น้อยลง)

**สาเหตุ:** โมเดลมี *attention budget* จำกัด ทุก token ที่ใส่เข้าไปกินงบนั้น
⇒ กฎข้อที่ 40 ไม่ได้เพิ่มความปลอดภัย — มันเจือจางกฎ 39 ข้อแรก

## ตัวเลขจริงจากของที่เกิดขึ้น

```
ไฟล์กติกาหลัก   18,487 → 116,034 ไบต์ ใน 8 วัน   (6.3 เท่า)
ต้นทุนบังคับต่อ session ก่อนเริ่มงาน   ~28,800 tokens
```
⚠️ **นับไบต์กับตัวอักษรไม่เท่ากัน** — ภาษาไทย 1 ตัวอักษร = 3 ไบต์ใน UTF-8
⇒ **ด่านคุมขนาดต้องนับตัวอักษร** ไม่งั้นเพดานจะเข้มกับภาษาที่ไม่ใช่อังกฤษ 3 เท่าโดยไม่ตั้งใจ

**หลังแยกชั้น:** ไฟล์กติกาหลักลดลง **58%** โดย**ไม่ตัดบทเรียนทิ้งสักข้อ**

## โครง 3 ชั้น

```
CLAUDE.md                    โหลดอัตโนมัติทุก session   ← กฎที่ห้ามพลาด (สั้นที่สุดเท่าที่ทำได้)
docs/team/CHARTER.md         บังคับอ่านก่อนเริ่มงาน      ← เขตไฟล์ + พิธีส่งงาน + ดัชนีบทเรียน
docs/team/lessons/<หมวด>.md  อ่านเมื่อเกี่ยวข้อง         ← บทเรียนสะสม
```

**หมวดที่ใช้ได้กับเกือบทุกโปรเจกต์:**

| หมวด | เนื้อหา |
|---|---|
| `measuring.md` | เครื่องมือวัด · เทสต์ · ด่าน · QA |
| `numbers.md` | กติกาการรายงานตัวเลข |
| `data-safety.md` | migration · trigger · ข้อมูลจริง (ถ้ามีฐานข้อมูล) |
| `layout.md` | งาน UI (ถ้าเป็นงานหน้าจอ) |

## ด่านคุมขนาด

`check-charter-size.mjs` — เกินเพดาน = ตีกลับ พร้อมข้อความว่า **"ย้ายไป lessons/"**

**ข้อความของด่านสำคัญพอๆ กับตัวด่าน:**
```
✅ ทางแก้ที่ถูก: ย้ายบทเรียนไป lessons/<หมวด>.md
🚫 ทางแก้ที่ผิด: ตัดเนื้อหาทิ้ง หรือขยายเพดาน
```
เพราะบทเรียนทุกข้อ**มาจากความผิดพลาดที่มีราคาจ่ายไปแล้ว** — การลบมันคือการจ่ายราคานั้นซ้ำ

## กติกาการคุยข้าม session

**ปัญหา "ข้อความสวนกัน"** — ทั้งสองฝั่งทำงานเสร็จแล้วส่งข้อความพร้อมกัน ⇒ ตอบเรื่องที่อีกฝั่งแก้ไปแล้ว
เกิดจริง **6 ครั้งในวันเดียว**

**ต้นเหตุเชิงโครงสร้าง:** คุยกันด้วย *ข้อความ* ซึ่ง "ส่งแล้วสถานะค้าง" — ไม่ใช่ *สถานะที่อ่านได้ตลอดเวลา*

### 3 กติกาที่แก้ได้จริง

1. **ก่อนส่งข้อความ ต้อง `git fetch` แล้วดูว่าปลายทางแก้ไปแล้วหรือยัง**
2. **การตัดสินใจของเจ้าของโปรเจกต์ต้องลง `decisions.md`** ไม่ใช่อยู่แค่ในบทสนทนา
3. **ข้อความ = คำตัดสิน + เหตุผล 1 บรรทัด + สิ่งที่ต้องทำ ≤3 ข้อ**
   รายละเอียดเขียนลงไฟล์แล้วอ้างถึง

📌 ข้อ 3 ไม่ใช่แค่ประหยัด token — **ข้อความยาวทำให้คำสั่งจริงจมอยู่กลางย่อหน้า ซึ่งเป็นตำแหน่งที่โมเดลอ่านพลาดที่สุด**

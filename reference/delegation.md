# การกระจายงาน — ใครทำ และส่งต่อยังไง

> เอกสารนี้เกิดจากวันที่ **coordinator ทำงานเองรวดเดียว 12 commit แตะ 27 ไฟล์**
> แล้วเจ้าของโปรเจกต์ทักว่า *"แปลกทำไมรอบนี้คุณไม่ส่งให้ทีมอื่นทำ"*
> ทุกข้อในนี้มีตัวเลขหนุนหลัง ไม่ใช่ความเห็น

---

## 🔴 มี 3 โหมด ไม่ใช่ 2 — และโหมดที่ 3 ไม่ส่งมอบอะไรเลย

| โหมด | ส่งมอบอะไร |
|---|---|
| **ทำเอง** | เสร็จแน่ · แต่เข้าคิวหลังงานอื่นของคนคนเดียวกัน |
| **เปิด session ใหม่** | ขนานได้จริง · จ่ายค่าตั้งต้น |
| **เขียน "→ แผนกนั้น: ..." ลงไฟล์แผนงาน** | 🔴 **ไม่มีอะไรเกิดขึ้น** |

**วัดจริง:** คำขอข้ามแผนกในไฟล์แผนงาน **8 ข้อ · ข้อเก่าสุดค้างมา 16 วัน**

> ก่อนถูกทัก "การกระจายงาน" ของ coordinator คือโหมดที่ 3 —
> **เขียนลงไฟล์แล้วรู้สึกว่าส่งต่อแล้ว**

**กติกา:** ไฟล์แผนงานเก็บ *ความรู้* ได้ แต่ **ห้ามนับเป็นการส่งงาน**
จะส่งต้องเปิด session ในงวดเดียวกัน · ไม่มี session = มันคือโน้ต ไม่ใช่คำขอ

## เกณฑ์ตัดสิน: **"งานถัดไปต้องรู้ผลของงานที่ทำอยู่ไหม"**

เกณฑ์ที่คนมักใช้คือ *"งานจบด้วย commit ไหม"* — **นั่นวัดที่ชนิดของผลลัพธ์ ซึ่งเป็นแกนที่ผิด**

```
ต้องรู้ผลก่อนถึงจะสั่งได้   → ทำเอง (เขียนคำสั่งไม่ได้ เพราะยังไม่รู้จะสั่งอะไร)
ไม่ต้องรู้                  → ส่งต่อทันที ไม่ต้องรอจบงานปัจจุบัน
```

**ตัวอย่างจากวันจริง — 12 commit ในสายเดียว:**

| | |
|---|---|
| commit 1–11 (งานความปลอดภัย) | **โซ่เดียวกัน** — เขียนคำสั่งของงานที่ 2 ก่อนจบงานที่ 1 ไม่ได้ เพราะตอนเปิดตารางถึงรู้ว่ามีบัญชีผู้ใช้ 877 ใบอ่านได้ ⇒ **ทำเองถูกแล้ว** |
| commit 12 (รื้อ UI) | **ไม่เกี่ยวกับ 11 ตัวแรกเลย** ⇒ ควรส่งต่อตั้งแต่นาทีแรก |

## 1 session = 1 **เขต** ไม่ใช่ 1 **งาน**

ค่าตั้งต้น (อ่านกติกา + บทเรียน + ไล่โค้ด) เป็น**ต้นทุนคงที่** ⇒ กวาดงานค้างของเขตนั้นใส่ใบเดียว
จ่ายครั้งเดียว และคนทำเห็นภาพรวมเขตตัวเอง ซึ่งดีกว่าเห็นทีละชิ้น

---

## session ที่ยัง**เปิดอยู่** → ส่งข้อความ อย่าเปิดใบใหม่

การส่งข้อความเข้า session ที่ยังมีบริบทอยู่ **ถูกกว่าการ brief ใหม่ทั้งใบเสมอ**
(Claude Code มีเครื่องมือ list/send message ระหว่าง session)

---

## หัวหน้าแผนกสร้าง **subagent** ได้ · เปิด **session** ใหม่ไม่ได้

- **subagent** = งานที่ไม่จบด้วย commit (วัด · กวาด · อ่าน log ยาว ๆ) ⇒ output ยาวอยู่ในบริบทของ subagent ไม่ใช่ของหัวหน้า
- 🚫 **ห้ามแตกเป็น session ต่อ** — ไม่งั้นไม่มีใครรู้ว่ามีกี่สายวิ่งอยู่ และเพดาน 3–5 พังทันที

---

## 🚫 พิจารณาแล้วไม่เอา: **"หัวหน้าแผนกถาวรที่เปิดค้างไว้ตลอด"**

ไอเดียคือ: เปิด session ประจำแผนกไว้ แล้วส่งข้อความสั่งงานแทนการเปิดใบใหม่ทุกครั้ง
**แก้ปัญหาค่าตั้งต้นได้จริง** แต่แลกด้วย 4 อย่างที่วัดได้:

| | ปัญหา | หลักฐาน |
|---|---|---|
| ① | **บริบทเน่า** — ค่าตั้งต้นจ่าย**ครั้งเดียว** แต่บริบทสะสมจ่าย**ทุกเทิร์น** | ไฟล์กติกา ~9k tokens อ่านครั้งเดียว · session ที่อยู่มาทั้งวันแบก 100k+ ทุกเทิร์น · พอเต็มจะถูกย่อ ⇒ เหลือ**บทสรุปที่ไม่ครบของงานตัวเอง** ซึ่งแย่กว่าอ่านไฟล์บทเรียนที่คัดไว้แล้ว |
| ② | **1 session = 1 worktree = 1 branch** | โมเดล merge คือ 1 งวด = 1 branch ⇒ ถ้ากองทุกงานบน branch เดียว **งานเสียใบเดียวบล็อกทั้งกอง** |
| ③ | **session ไม่ได้อยู่เองเฉย ๆ** | ตรวจจริง: session ทั้ง 12 ใบในระบบ `isRunning: false` — "หัวหน้าประจำ" ที่จริงคือ*กระบวนการที่หยุดแล้ว*รอปลุก |
| ④ | **ขยะสะสม** | 47 branch ชั่วคราว + 16 worktree ค้างในเครื่อง |

### 🔑 จุดที่คนมองข้าม

> **ค่าตั้งต้นซื้อของบางอย่างอยู่ — คนอ่านที่ยังไม่ได้เชื่ออะไรของตัวเอง**

วันเดียวกันนั้น coordinator สร้าง **ด่านที่เขียวทั้งที่ไม่ได้ตรวจอะไร 4 ครั้ง** ส่วนหนึ่งเพราะเชื่อข้อสรุปของตัวเองเมื่อชั่วโมงก่อน
**หัวหน้าถาวรจะแบกความเชื่อผิดนั้นไปทุกงานที่เหลือ**

**หลักฐานฝั่งตรงข้าม:** session ใหม่ 2 ใบที่เปิดวันนั้น เสร็จ + auto-merge เอง
อยู่ในเขตตัวเองทั้งคู่ และ **เขียนเทสต์เพิ่มมาเองโดยไม่ได้สั่ง** (241 + 114 บรรทัด)

### เอาแทน: **อายุของหัวหน้าแผนก = ความยาวของกะงาน**

2–5 ชิ้นในเขตเดียว แล้วจบ · ความรู้ที่ต้องอยู่ต่อ **ไม่ได้อยู่ในบริบทของ session**
แต่อยู่ใน `lessons/` + `zones/<แผนก>.md` + `status/<แผนก>.md`

> **270 งวดผ่านระบบนี้โดยไม่ต้องมี session ถาวรสักใบ**

**ทางที่ถูกไม่ใช่เลิกจ่ายค่าตั้งต้น — แต่คือทำให้มันถูกลง** ⇒ ดูหัวข้อบรีฟรายเขตใน `SKILL.md`

## 🚩 coordinator ทำเองมากไป — ด่านจับไม่ได้ ต้องเช็คเอง

**ด่านเขตไฟล์อ่านจากชื่อ branch** (`parallel/<แผนก>-`)
⇒ **coordinator ที่ทำงานบน `main` ไม่เคยเข้าไปอยู่ในขอบเขตที่ด่านตรวจเลยสักครั้ง**
(ด่านทำงานถูกตามที่เขียนไว้ ไม่ได้พัง — แค่ไม่มีใครเอา coordinator เข้าไปให้มันตรวจ)

**ถามตัวเอง 3 ข้อก่อนลงมือแก้ไฟล์:**

| | ถ้า | ⇒ |
|---|---|---|
| ① | ไฟล์อยู่เขตแผนกอื่น และงาน**จบด้วย commit** | **ส่งให้แผนกนั้น** |
| ② | ไฟล์**ไม่มีเจ้าของ**ใน `ownership.json` | **ยกเขตให้แผนกที่ใกล้ที่สุดก่อน** แล้วค่อยส่ง |
| ③ | ต้องตัดสินใจระหว่างทางและ**เถียงกับเจ้าของโปรเจกต์ได้** · หรือเป็นไฟล์ที่ล็อกไว้ให้ coordinator | ทำเอง ✅ |

**ข้อยกเว้นที่ทำเองได้จริง:** งานที่ *ต้นเหตุ* อยู่ที่ไฟล์กลาง/ฐานข้อมูล แล้วปลายทางกระจายหลายเขต
(เช่น เปลี่ยนสิทธิ์ 1 ตาราง แล้ว 6 หน้าอ่านตารางนั้น)
— **แต่ต้องแจ้งในรายงานจบงานว่าแตะเขตไหนไปบ้าง ไม่ใช่เงียบ**

> 🔑 **"ทำเองเร็วกว่าเขียนคำสั่ง" เป็นจริงเสมอในระยะสั้น และเป็นเหตุผลที่ระบบขนานตายทุกครั้ง**
> ต้นทุนไม่ได้อยู่ที่งวดนี้ — มันอยู่ที่งวดหน้าที่ทุกอย่างยังต้องผ่านคนเดิมคนเดียว
